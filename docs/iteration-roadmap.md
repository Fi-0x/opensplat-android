# OpenSplat Android 迭代路线

更新于 2026 年 11 月 20 日。

## 从原型到安卓主线

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| `mobile3dgs` 原型 | 用 COLMAP MVS、RGB-D 对照和 CUDA 训练研究初始化、图像监督及新视角画质 | [原型记录](../README.legacy.md) |
| OpenSplat Android | 迁移到 OpenSplat Android，沿用 ARCore 采集、Brush 端侧训练和 PLY 输出 | Android 15 模拟器已验证离线训练及报告导出 |
| 固定公开基准 | 使用 TUM RGB-D 的已知位姿和训练帧深度初始化，在相同视角比较分辨率、训练预算和初始化策略 | 640×480 原版 2000 步可作为日常实验配置 |
| 补视角覆盖 | 用候选训练帧的几何覆盖评估替换收益，同时控制原有覆盖损失 | 保守换帧在两个室内序列改善了部分视角 |
| 项目实拍 | 在目标手机采集一段室内素材，检查导出位姿和点云并做配对训练 | 真机测试 APK 已编译，等待实拍 ZIP |

## 实验结果

以下分数来自各模型在同一对照内的统一重渲染。每一组的帧划分、分辨率和评分口径见对应说明，跨场景的绝对分数无需直接比较。

- **训练预算。** TUM `freiburg1_desk` 上直接设为 2000 步，六张 640×480 验证图平均 **17.60 dB / 0.6649 SSIM**。5000 步预算的第 2000 步中途模型是 **17.57 dB / 0.6649**。同次训练的 5000 步终点为 **17.58 dB / 0.6433**，点数从中途约 8.9 万涨到 24.2 万。
- **初始化。** 固定 2 万点的 RGB-D 重采样在 2000 步时使均值从 **17.60 降至 17.54 dB**。PocketGS 启发的表面对齐初始化已确认能导入 Brush 的尺度和旋转，1000 步时由各向同性对照的 **17.23 降至 17.17 dB**。这里只验证了初始化，PocketGS 的几何构建和移动端渲染仍待独立验证。
- **Desk 场景选帧。** 低覆盖区有有效验证深度的 7,785 个像素中，98.6% 对应的表面点落在全部 37 张训练图的视野外。自动换 8 帧虽然改善缺口，但七张留出图平均从 **19.62 降至 18.98 dB**。把替换拆开后，保守换一帧在两个种子中分别提高六张验证图均分 **0.36 / 0.39 dB**，七张留出图均分仅提高 **0.07 / 0.06 dB**。最明显的收益在局部缺口，留出集用于回归检查。
- **Room 场景验证。** 在 TUM `freiburg1_room` 中，固定初始点云和 37 张训练图，只替换一张。六张预先固定的留出图平均从 **15.13 提高至 15.59 dB**，SSIM 从 **0.6028 提高至 0.6113**。主要收益集中在一帧，该帧提高 **2.40 dB**，低覆盖比例从 **3.90% 降至 0.19%**。

## 下一步验收

1. **采集。** 用支持 ARCore 的目标安卓手机拍摄一个静止桌面或房间角落。停止采集后，等待处理并在资料库分享采集 ZIP。
2. **检查输入。** 核对导出图像、相机内外参和初始化点云，确认数据可用于同视角渲染，并评估采集流程是否提供足够的几何信息来判断覆盖。
3. **配对训练。** 从同一次采集中固定一组留出相机。用相同训练图数量、初始点云和 2000 步预算，对比现有选帧与保守换一帧。记录缺口覆盖、局部 PSNR、留出均分及明显退步的视角。
4. **真机性能。** 画质收益复现后，用目标手机核对训练耗时、内存和发热，再决定是否将选帧策略推广到默认流程。
